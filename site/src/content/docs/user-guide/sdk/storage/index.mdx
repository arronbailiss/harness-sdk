To persist agent state between restarts, pass a Storage backend
to the plugins that need it. You pick the backend once, and
consumers like [Context Offloader](../plugins/context-offloader.mdx)
and [Memory](../memory/overview.mdx) handle the rest. This is the
single place persistence backends are documented.

[Session Management](../agents/session-management.mdx) also composes a Storage
backend. Its page documents how the selected SDK resolves storage and which
compatibility managers configure persistence directly.

## Precedence

Storage resolves in this order for each subsystem:

1. **Explicit**: storage passed directly to the plugin
2. **Agent-level**: the agent's
   <Syntax py="storage" ts="storage" rs="storage" /> parameter
   (namespaced automatically)
3. **Fallback**: `InMemoryStorage` for Context Offloader. Session storage uses
   <Syntax
     py="LocalFileStorage"
     ts="an explicit-storage requirement"
     rs="an explicit-storage requirement"
   />.

<Tab label="Python">

#### Required S3 permissions

The credentials used by `S3Storage` need these permissions:

- `s3:PutObject` to create and update data
- `s3:GetObject` to retrieve data
- `s3:DeleteObject` to delete data
- `s3:ListBucket` to list keys under the configured prefix

This policy grants the required permissions for one bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::my-agent-sessions/*"
    },
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-agent-sessions"
    }
  ]
}
```

You cannot pass both a region and a pre-configured client; pick
one or the other.

## Custom backends

Implement four async methods
(<Syntax
  py="write, read, delete, list"
  ts="write, read, delete, list"
  rs="write, read, delete, list"
/>)
and pass your class anywhere a `Storage` is accepted. In Python,
`Storage` is a
[protocol](@api/python/strands.storage.storage#Storage); in
TypeScript, implement the
[interface](@api/typescript/Storage).

Community backends can add methods beyond the core four (e.g.
`search` for vector similarity, or structured queries for
databases like DynamoDB). Plugins that only need basic
persistence use the four standard methods; plugins that need
richer access can check for and use the extra surface your
backend provides.

When using agent-level storage, each subsystem scopes its keys
under its own prefix automatically (`session/`, `offloader/`),
so you never need to worry about collisions. If you write a
custom plugin that consumes agent-level storage, call
<Syntax
  py="storage.namespace('my-prefix/')"
  ts="storage.namespace('my-prefix/')"
  rs='storage.namespace("my-prefix/")'
/>
to claim your own prefix and avoid overlapping with other
subsystems.
