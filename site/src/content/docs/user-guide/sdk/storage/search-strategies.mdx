Storage backends expose a

<Syntax py="search()" ts="search()" rs="search()" /> method that delegates to a pluggable search strategy. A strategy
implements the
<Syntax py="SearchStrategy" ts="SearchStrategy" rs="SearchStrategy" />
protocol/interface: given a storage backend and a query string, it returns a ranked list of matching keys with relevance
scores. Strategies that maintain an index use
<Syntax py="index()" ts="index()" rs="index()" /> to update incrementally on each write;
<Syntax
  plain
  py="strategies that search on the fly implement it as a no-op"
  ts="strategies that search on the fly omit it"
  rs="strategies that search on the fly use the default no-op"
/>
.

All shipped backends default to
`KeywordSearchStrategy`. Pass a different strategy via
the

<Syntax py="search_strategy" ts="searchStrategy" rs="search_strategy" /> parameter on any built-in backend to override
it.

## KeywordSearchStrategy

The default strategy tokenizes
the query into lowercased words, reads every key in
storage, and scores each entry by the number of distinct
query tokens that appear in the key and content. No
index, embedding model, or external dependency required.

## BM25 search

<Tabs>
<Tab label="Python">

`Bm25SearchStrategy` uses the built-in `sqlite3` FTS5
module. It scores results by term frequency, inverse document frequency, and
document length normalization. The strategy works only with
`LocalFileStorage`, keeps its index beside the storage directory, and cannot
be used with a sandboxed store. It indexes entries at write time and does not
backfill existing content.

```python
--8<-- "user-guide/sdk/storage/search-strategies.py:bm25_search"
```

Call `close()` when the strategy is no longer needed to release its SQLite
connection.

</Tab>
<Tab label="TypeScript">

`QmdSearchStrategy` uses
[QMD](https://github.com/tobi/qmd) and re-indexes the
storage directory on each search, so existing content
is always searchable. It works only with `LocalFileStorage`, cannot be used
with a sandboxed store, and requires `@tobilu/qmd` as a peer dependency:

```bash
npm install @tobilu/qmd
```

```typescript
--8<-- "user-guide/sdk/storage/search-strategies.ts:bm25_search"
```

Call `close()` when the strategy is no longer needed to release its resources.

</Tab>
<Tab label="Rust">

The SDK does not ship a BM25 or QMD strategy. Use `KeywordSearchStrategy` for
small-to-medium stores, or implement `SearchStrategy` for another index.

## Passing a strategy to a storage backend

Every built-in backend (`InMemoryStorage`,
`LocalFileStorage`, `S3Storage`) accepts a

<Syntax py="search_strategy" ts="searchStrategy" rs="search_strategy" /> parameter. When set, writes automatically call
the strategy's
<Syntax py="index()" ts="index()" rs="index()" /> method, and
<Syntax py="search()" ts="search()" rs="search()" /> delegates to the strategy instead of the default keyword scan.

## Writing a custom strategy

To rank results your own way, implement

<Syntax py="SearchStrategy" ts="SearchStrategy" rs="SearchStrategy" />
yourself. Its <Syntax py="search()" ts="search()" rs="search()" />
method receives the storage backend and the query, and returns
<Syntax py="StorageSearchResult" ts="StorageSearchResult" rs="StorageSearchResult" />
entries (key, score, and optionally the stored bytes), best match first. Read entries through the storage passed in,
using
<Syntax py="list()" ts="list()" rs="list()" /> and
<Syntax py="read()" ts="read()" rs="read()" />, so the strategy works with every backend. When the search already read
an entry's bytes, include them in the result as `data` so callers don't have to read the entry again.

If your strategy keeps its own index, such as a vector
store or a full-text index, update it in

<Syntax py="index()" ts="index()" rs="index()" />. The backend calls it on every write with the key and the stored
bytes.

The example below ranks entries by how often the exact
query phrase appears.

<Tabs>
<Tab label="Python">

`SearchStrategy` is a protocol, so any class with async
`index()` and `search()` methods works without
subclassing. `index()` is required; a strategy that
searches on the fly implements it as a no-op.

```python
--8<-- "user-guide/sdk/storage/search-strategies.py:custom_strategy"
```

To pass a strategy to a sandboxed `LocalFileStorage`,
declare `requires_host_fs: Literal[False] = False` on
the class, as `KeywordSearchStrategy` does. The type
checker rejects a sandboxed `LocalFileStorage` with a
strategy that doesn't declare it. If your strategy
reads or writes the host filesystem directly, declare
`requires_host_fs: Literal[True] = True` instead, as
`Bm25SearchStrategy` does, and `LocalFileStorage`
raises `ValueError` when a sandbox is set.

</Tab>
<Tab label="TypeScript">

Any object or class with a `search()` method works.
`index()` is optional; a strategy that searches on the
fly omits it.

```typescript
--8<-- "user-guide/sdk/storage/search-strategies_imports.ts:custom_strategy_imports"

--8<-- "user-guide/sdk/storage/search-strategies.ts:custom_strategy"
```

If your strategy reads or writes the host filesystem
directly instead of going through the storage, declare
`readonly requiresHostFs = true` on it.
`LocalFileStorage` then throws when a sandbox is set,
as it does for `QmdSearchStrategy`.

</Tab>
