Strands harness is a thin composition layer, not a framework of its own. The substance lives in the
[Strands Harness SDK](../../sdk/): the model loop, tools, context
management, sessions, memory, and hooks. Strands harness's job is to assemble those building blocks
into one agent with tested defaults and a tuned system prompt, so you do not wire them up
yourself. This page is for readers who know the Strands Harness SDK, or want to, and need to see exactly
where Strands harness sits and how to reach past it.

## The composition model

The factory does three things in order: it resolves your options into concrete Strands Harness SDK objects
(a `Model` from a `provider/name` string, a memory manager, intervention handlers), it
assembles the built-in tools, plugins, subagents, and behaviors, and it constructs a plain
`Agent` from the result. Nothing wraps that agent afterward. The built-in tools are
ordinary registered tools, the built-in integrations are ordinary plugins, and sessions
and memory use the Strands Harness SDK's own managers.

## The return value is a plain Agent

The harness factory returns a plain Strands `Agent`, the same type you get from
the Strands Harness SDK directly. There is no Strands harness type around it.
Because you hold a normal `Agent`, the full Strands Harness SDK is available, and
nothing about Strands harness blocks a feature the Strands Harness SDK offers.

## Compose Strands Harness SDK features alongside Strands harness's defaults

SDK configuration fields pass through the harness factory, and an explicit value wins
over the harness default it replaces. Pass your own `plugins` or `interventions`
alongside Strands harness's and they compose:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness
    from strands.vended_interventions.hitl import HumanInTheLoop
    from strands.vended_plugins.todos import Todos

    agent = create_harness(
        context_manager="agentic",
        plugins=[Todos()],
        interventions=[HumanInTheLoop()],
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'
    import { HumanInTheLoop } from '@strands-agents/sdk/vended-interventions/hitl'
    import { Todos } from '@strands-agents/sdk/vended-plugins/todos'

    const agent = await createHarness({
      contextManager: 'agentic',
      plugins: [new Todos()],
      interventions: [new HumanInTheLoop()],
    })
    ```
  </Tab>

## Modify the agent after construction

You can also change the agent once you have it. The system prompt, tools, and every other
field are yours to adjust:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness()
    agent.system_prompt += "\n\nAlways cite file paths as file:line."
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness()
    agent.systemPrompt += '\n\nAlways cite file paths as file:line.'
    ```
  </Tab>

## The building blocks are exported too

Strands harness exports the pieces its factory composes, so you can reuse them without
building the whole agent:

<Tabs>
  <Tab label="Python">
    `HARNESS_CONTRACT` contains the model-neutral behavioral contract.
    `build_system_prompt` combines it with your instructions and request-scoped context.
    `resolve_memory` and `resolve_interventions` expose the harness's memory and
    intervention builders.
  </Tab>
  <Tab label="TypeScript">
    `HARNESS_CONTRACT` contains the model-neutral behavioral contract.
    `buildSystemPrompt` combines it with your instructions and request-scoped context.
  </Tab>
  <Tab label="Rust">
    `HARNESS_CONTRACT` contains the model-neutral behavioral contract.
    `build_system_prompt` combines it with your instructions and request-scoped context.
  </Tab>
</Tabs>

If you build an agent from Strands Harness SDK building blocks directly, you can still borrow Strands harness's tuned
prompt:

<Tabs>
  <Tab label="Python">
    ```python
    from strands import Agent
    from strands_harness import HARNESS_CONTRACT, build_system_prompt

    agent = Agent(system_prompt=build_system_prompt("You are a migration assistant."))
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { Agent } from '@strands-agents/sdk'
    import { buildSystemPrompt } from '@strands-agents/harness'

    const agent = new Agent({ systemPrompt: buildSystemPrompt('You are a migration assistant.') })
    ```

## When to reach for which

Use Strands harness when you want a capable agent fast and its defaults fit. Reach for the Strands Harness SDK
directly when you are building something whose shape Strands harness does not assume: a bespoke tool
set with no shell, a custom agent loop, or an
[orchestration of many agents](../../sdk/multi-agent/multi-agent-patterns/).
The two are not a fork in the road. Start on Strands harness, and because it returns a plain `Agent`,
you can drop to the raw Strands Harness SDK building blocks for the parts that need it without rewriting
what already works.

When a behavior looks wrong, it helps to confirm whether it originates in Strands harness or the
underlying Strands Harness SDK, since Strands harness is mostly composition over Strands Harness SDK behavior.
