Strands harness uses Amazon Bedrock by default. Pass `model` to pick another model, and
pass `effort` to change how hard the agent reasons.

## Point Strands harness at a model

You pick a model by passing `model`, which accepts a `provider/name` string, a bare
Amazon Bedrock model id, or a ready-made Strands `Model` instance.

<Tabs>
  <Tab label="Python">
    Provider aliases include `bedrock`, `bedrock-mantle`, `anthropic`, `openai`,
    `google`, `ollama`, and `litellm`.
  </Tab>
  <Tab label="TypeScript">
    Provider aliases include `bedrock`, `bedrock-mantle`, `anthropic`, `openai`,
    `google`, `ollama`, and `litellm`.
  </Tab>
  <Tab label="Rust">
    Provider aliases include `bedrock`, `bedrock-mantle`, `anthropic`, and `openai`.
    The default Cargo features enable all four providers, plus MCP, Cedar, and the
    Monty worker.

    Keep default features unless you are deliberately removing optional capabilities.
    If you disable them, enable the provider and every harness capability your
    application uses:

    ```bash
    cargo add strands-harness --no-default-features \
      --features openai,mcp,cedar,monty-pool
    ```

    A model string whose provider feature is disabled fails during harness construction
    and names the feature to enable. The `mantle` feature also enables `openai`.
  </Tab>
</Tabs>

A string with no provider prefix is treated as a bare Amazon Bedrock id. On `bedrock`,
Claude models run through the Anthropic Messages API with Anthropic's Bedrock client;
every other Amazon Bedrock model uses Converse.

For a provider Strands harness does not have an alias for, or for a model you have already
configured (custom endpoint, credentials, request fields), build the `Model` instance
yourself and pass it. Strands harness uses it as-is:

<Tabs>
  <Tab label="Python">
    ```python
    from strands.models import BedrockModel
    from strands_harness import create_harness

    model = BedrockModel(model_id="global.anthropic.claude-opus-5-5", region_name="us-west-2")
    agent = create_harness(model=model)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { BedrockModel } from '@strands-agents/sdk'
    import { createHarness } from '@strands-agents/harness'

    const model = new BedrockModel({ modelId: 'global.anthropic.claude-opus-5-5' })
    const agent = await createHarness({ model })
    ```
  </Tab>
  <Tab label="Rust">
    ```rust
    --8<-- "user-guide/harness/configure/model.rs:model_instance"
    ```
  </Tab>
</Tabs>

An unknown provider prefix fails at construction with the list of supported providers, so
a typo surfaces immediately rather than as a request error later.

## Set reasoning effort

`effort` maps one reasoning level onto whatever each provider's API expects:

- `auto` (the default) uses the level the model's vendor runs it at in its own
  harness (Claude Code, Codex, or Gemini CLI), taken from the
  [shared model info][model-info]:
  `medium` on Claude Opus 5.5, `high` on Opus 5, and `low` on GPT-6.1 Sol. A
  model without a vendor default gets `high`.
- `minimal`, `low`, `medium`, `high`, `xhigh`, and `max` set it explicitly.
- `off` turns reasoning off.

      <Tab label="TypeScript">

      </Tab>
      <Tab label="Rust">
        ```rust
        --8<-- "user-guide/harness/configure/model.rs:harness_effort"
        ```
      </Tab>
    </Tabs>
  </Tab>
  <Tab label="SDK">
    <Tabs>
      <Tab label="Python">
        ```python
        from strands import Agent
        from strands.models import BedrockModel

        bedrock_model = BedrockModel(
            model_id="global.anthropic.claude-sonnet-5",
            additional_request_fields={
                "thinking": {"type": "enabled", "budget_tokens": 4096}
            },

        agent = Agent(model=bedrock_model)
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript

          modelId: 'global.anthropic.claude-sonnet-5',
          additionalRequestFields: {
            thinking: { type: 'enabled', budget_tokens: 4096 },
          },
        })
        const agent = new Agent({ model: bedrockModel })
        ```
      </Tab>
      <Tab label="Rust">
        Configure reasoning on the provider model before passing it to the agent.
        The harness-level `Effort` mapping applies only to model strings.
      </Tab>
    </Tabs>
  </Tab>
</Tabs>

A level a provider does not accept fails at construction rather than mid-request. Some
providers accept finer levels (for example `minimal` or `xhigh`). Strands harness
validates against the resolved provider and model, so use the levels the provider
documents for your model.

Reasoning does not apply to a pre-built `Model` instance: configure reasoning on the
instance itself when you pass one.

## Note on web search and caching

Two model-level features follow from the provider you pick.

<Tabs>
  <Tab label="Python">
    Native `web_search` works on OpenAI, Anthropic, Google, and supported models on
    `bedrock-mantle`. The harness configures prompt caching on Amazon Bedrock,
    Anthropic, OpenAI, and `bedrock-mantle`. Google and LiteLLM cache
    automatically; Ollama does not support prompt caching.
  </Tab>
  <Tab label="TypeScript">
    Native `web_search` works on OpenAI, Anthropic, Google, and supported models on
    `bedrock-mantle`. The harness configures prompt caching on Amazon Bedrock,
    Anthropic, OpenAI, and `bedrock-mantle`. Google and LiteLLM cache
    automatically; Ollama does not support prompt caching.
  </Tab>
  <Tab label="Rust">
    Native `web_search` works on OpenAI, Anthropic, and supported models on
    `bedrock-mantle`. The harness configures prompt caching for every supported
    provider.
  </Tab>
</Tabs>

Both are covered where you enable them:
[web access](../../tools/web-access/) and
[manage context and caching](../context-and-caching/).

For the full option list, see the
[configuration reference](../../reference/configuration/).
