Background tasks let a tool run while the agent keeps working, instead of blocking the
loop until it finishes. Strands harness exposes this SDK capability through the
<Syntax py="background_tasks" ts="backgroundTasks" rs=".background_tasks" />
option.

## What runs in the background by default

The built-in `generalist`
[delegate](../subagents/) always runs in the background, so
the main agent can continue while the delegate works through its subtask. By default the
model may also choose background execution for any other compatible tool; the invocation
waits for the result and continues with it.

## Tune or disable it

The
<Syntax py="background_tasks" ts="backgroundTasks" rs=".background_tasks" />
option accepts a boolean or a policy object. Pass
`false` to disable background tasks, or a policy to control which tools may run in the
background, along with concurrency, completion, and timeouts. With a policy, the
`generalist` still runs in the background: Strands harness forces it there and merges
that into your policy.

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    no_background = create_harness(background_tasks=False)
    scoped = create_harness(
        background_tasks={"agentic": ["long_running_report"]}
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const noBackground = await createHarness({ backgroundTasks: false })
    const scoped = await createHarness({
      backgroundTasks: { agentic: ['long_running_report'] },
    })
    ```
  </Tab>
  <Tab label="Rust">
    ```rust
    --8<-- "user-guide/harness/configure/background-tasks.rs:configure"
    ```
  </Tab>
</Tabs>

The default policy is equivalent to `{ agentic: ['*'] }`: the model may run any compatible
tool in the background.

## Cancel background work

Cancelling the current invocation leaves background tasks running. To stop them
too, enable background-task cancellation on the cancel call:

<Tabs>
  <Tab label="Python">
    ```python
    agent.cancel(cancel_background_tasks=True)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    agent.cancel({ cancelBackgroundTasks: true })
    ```
  </Tab>
  <Tab label="Rust">
    ```rust
    --8<-- "user-guide/harness/configure/background-tasks.rs:cancel"
    ```
  </Tab>
</Tabs>

If the invocation had already finished its turn and was only waiting for background tasks, it
returns that turn's result, and the cancelled task results are delivered on the next invocation.

## The CLI

The Strands harness CLI runs on the TypeScript library, so the `generalist` runs in the background
there too. The CLI does not expose a flag to change the background-tasks policy; use the
library when you need to tune it.

For the full option list, see the
[configuration reference](../../reference/configuration/).
