The `environment` integration is a plugin rather than a tool. It shapes how the agent
works without being something the model calls like `shell` or `read`, and it is on by
default. Python and TypeScript also keep an opt-in, deprecated harness `todos` plugin.
Rust uses the SDK `Todos` plugin directly.

## todos

:::caution[Moved to the SDK]
The harness `todos` built-in is deprecated and is removed in a later harness minor. The
plugin now ships in the SDK as `Todos`: construct it yourself and pass it in `plugins`.
[Todos](../../../sdk/plugins/todos/) documents what it does and how to configure it, and
[issue #5279](https://github.com/strands-agents/harness-sdk/issues/5279) tracks the move.
:::

In Python and TypeScript, naming `todos` in the harness built-in plugins still adds the
`todo_write` tool and keeps the list in view, but it warns on construction. Rust exposes
task tracking only through the SDK plugin. Moving to the SDK plugin changes how you attach
it and nothing about how the agent behaves:

<Tabs>
  <Tab label="Python">
    ```python
    from strands import Agent
    from strands.vended_plugins.todos import Todos

    agent = Agent(plugins=[Todos()])
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { Agent } from '@strands-agents/sdk'
    import { Todos } from '@strands-agents/sdk/vended-plugins/todos'

    const agent = new Agent({ plugins: [new Todos()] })
    ```
  </Tab>
  <Tab label="Rust">
    ```rust
    --8<-- "user-guide/harness/tools/todos-and-environment.rs:todos"
    ```
  </Tab>
</Tabs>

In Python and TypeScript, drop `todos` from the harness built-in plugins when you add the
SDK plugin. Keeping both registers `todo_write` twice and creates a name conflict. Rust
has no harness `todos` entry to remove.

## environment

The `environment` plugin injects a small block of working-environment context before each
user turn:

- The platform and the current date.
- The working directory.
- The project's `AGENTS.md`, included in full up to a cap (about 16 KB); a longer file is
  truncated with a marker, and the agent can read the rest on demand.
- Links (not contents) to other `AGENTS.md` and `README.md` files found a couple of levels
  down, so the block stays small and the agent reads them only as needed.

Everything is read through the agent's [sandbox](../../../sdk/sandbox/), so
the platform, directory, and files describe where the agent actually runs. The date is
injected each turn (rather than baked into the system prompt) precisely so it does not
change the cached prompt prefix; the rest is discovered once and reused.

## Select or disable them

The built-in-plugins option selects these by name and defaults to `["environment"]`.
Python and TypeScript can still name `todos` during the deprecation window. Rust uses
the SDK `Todos` plugin directly. Pass an empty list to turn the harness plugins off:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(builtin_plugins=["todos", "environment"])
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness({ builtinPlugins: ['todos', 'environment'] })
    ```
  </Tab>
  <Tab label="Rust">
    ```rust

    ```
  </Tab>
</Tabs>

For the plugin system these build on, see the Strands Harness SDK's
[plugins](../../../sdk/plugins/) documentation.
