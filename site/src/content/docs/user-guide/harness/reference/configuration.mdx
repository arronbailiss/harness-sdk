This is the lookup layer for the Strands harness factory (`create_harness` in Python and
Rust, `createHarness` in TypeScript). Every argument is optional. The three libraries
expose the same concepts, spelled for each language. For practical examples, follow the
links into the configure and tools guides.

## Options

| Python | TypeScript | Rust | Default | Purpose |
|---|---|---|---|---|
| `model` | `model` | `.model` | Bedrock | Model string, router, or instance. |
| `effort` | `effort` | `.effort` | auto | Reasoning effort. |
| `instructions` | `instructions` | `.instructions` | none | Domain prompt block. |
| `tools` | `tools` | `.tools` | none | Consumer tools. |
| `plugins` | `plugins` | `.plugins` | none | Consumer SDK plugins. |
| `mcp_servers` | `mcpServers` | `.mcp_servers` | none | MCP server source. |
| `builtin_tools` | `builtinTools` | `.builtin_tools` | all | Harness tools. |
| `web_fetch.model` | same | `WebFetchConfig::model` | provider | Fetch model. |
| `caching` | `caching` | `.caching` | on | Prompt caching. |
| `context_manager` | `contextManager` | `.context_manager` | auto | Context policy. |
| `session.id` | same | `SessionConfig::id` | generated | Conversation id. |
| `session.dir` | same | `SessionConfig::dir` | `./.agent/sessions` | Session storage. |
| `skills` | `skills` | `.skills` | `./.agent/skills` | Agent Skills sources. |
| `builtin_plugins` | `builtinPlugins` | `.builtin_plugins` | environment | Plugins. |
| `memory` | `memory` | `.memory` | on | Long-term memory. |
| `memory.dir` | same | `MemoryConfig::dir` | `./.agent/memory` | Memory storage. |
| `memory.stores` | same | `MemoryConfig::stores` | none | Custom stores. |
| `interventions` | same | `.interventions` | none | Tool-call gates. |
| `background_tasks` | `backgroundTasks` | `.background_tasks` | agentic | Policy. |

## Value notes

- **`effort`** uses the string levels `"auto"`, `"off"`, `"minimal"`, `"low"`,
  `"medium"`, `"high"`, `"xhigh"`, and `"max"` in Python and TypeScript. Rust
  uses the matching `Effort` variants, such as `Effort::Auto` and
  `Effort::High`. A level the resolved provider rejects fails at construction.
- **`caching`** accepts `"auto"`/`True` to enable and `False`/`None` to disable
  in Python, with the equivalent values in TypeScript. In Rust, omit the option
  for the default or call `.caching(true)` / `.caching(false)`. Disabling it has
  no effect where caching is automatic. Enabling it explicitly on a `Model`
  instance is ignored with a warning.
- **`context_manager`** accepts `"auto"`, `"agentic"`, and `False`/`None` in
  Python, with the equivalent values in TypeScript. Rust uses
  `ContextManagerStrategy::{Auto, Agentic, Disabled}`. Disabling context
  management also disables context offloading.
- **`memory`** accepts `True` to enable and `False`/`None` to disable in Python,
  with the equivalent values in TypeScript. Rust uses `.memory(true)` /
  `.memory(false)` or a `MemoryConfig`. An explicit SDK memory manager takes
  precedence.
- **`builtin_tools`** accepts a list of names or a per-tool configuration in
  Python and TypeScript. Rust accepts `BuiltinToolName` values or a
  `BuiltinToolsConfig`.
- **`builtin_plugins`** accepts a list of names in Python and TypeScript. Rust
  accepts `BuiltinPluginName` values. Rust's only harness built-in plugin is
  `Environment`; use the SDK's `Todos` plugin for task tracking.

## Passthrough to the Agent

In Python, any keyword the factory does not name is forwarded to the underlying `Agent`
constructor. TypeScript's `HarnessAgentOptions` extends the SDK's `AgentConfig` minus the
fields the harness owns, while Rust exposes the remaining typed `AgentConfig` fields
directly on `HarnessAgentOptions`. In every language, an explicit SDK field takes
precedence over the harness default it replaces. For example, the SDK system prompt
replaces `instructions`, and an SDK memory manager replaces `memory`. See
[compose with the Strands Harness SDK](../../composing-with-sdk/).

## Exported building blocks

Beyond the factory, Strands harness exports the pieces it composes:
`HARNESS_CONTRACT`, `build_system_prompt` / `buildSystemPrompt`, and language-specific
builders. Python also exports `resolve_memory` and `resolve_interventions`. These are
documented in
[compose with the Strands Harness SDK](../../composing-with-sdk/).
